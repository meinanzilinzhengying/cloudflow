# CloudFlow 发布质量门禁检查清单

> 本文档用于在每次发布前进行系统性质量检查，确保只有满足所有门禁标准的版本才能进入生产环境。

---

- [ ] 所有 Go 文件通过 `go fmt` 检查（无格式差异）
- [ ] 所有 Go 文件通过 `goimports` 检查（无导入排序问题）
- [ ] 无未使用的导入（`go vet` 通过）
- [ ] 无未使用的变量（`go vet` 通过）

### 1.2 静态分析
- [ ] `go vet ./services/...` 无错误
- [ ] `go vet ./pkg/...` 无错误
- [ ] 无 `// TODO` 或 `// FIXME` 遗留（或已登记为后续 Issue）
- [ ] 无 `HACK` 或 `XXX` 标记（或已记录技术债务）

### 1.3 编译检查
- [ ] `alert-engine` 编译通过
- [ ] `data-plane` 编译通过
- [ ] `query-service` 编译通过

- [ ] `tenant-service` 编译通过

## 三、性能基准门禁 (Performance Benchmark Gates)

### 3.1 响应延迟
- [ ] P50 延迟 < 50ms（HTTP API）
- [ ] P95 延迟 < 100ms（HTTP API）
- [ ] P99 延迟 < 200ms（HTTP API）
- [ ] gRPC 调用 P99 < 50ms

### 3.2 吞吐量
- [ ] 单实例 HTTP QPS ≥ 1000
- [ ] 单实例 gRPC QPS ≥ 5000
- [ ] 数据平面处理 ≥ 10K flows/sec

### 3.3 资源消耗
- [ ] 空闲 CPU < 5%
- [ ] 内存使用 < 70%（告警前阈值）
- [ ] Goroutine 数量稳定（无泄漏）
- [ ] GC 暂停时间 < 10ms

### 3.4 稳定性测试
- [ ] 24 小时稳定性测试通过
  - 错误率 < 1%
  - 内存无持续增长（每小时增长 < 5MB）
  - Goroutine 无持续增长
  - 服务无重启/崩溃
- [ ] 48 小时稳定性测试（重大版本）
- [ ] 故障注入测试通过
  - 模拟依赖服务宕机
  - 验证降级策略生效
  - 验证熔断器正确工作

## 八、回滚方案 (Rollback Plan)

### 8.1 触发条件
- 错误率超过 1%（持续 5 分钟）
- P99 延迟超过 200% 基线（持续 10 分钟）
- 任何服务崩溃/重启超过 3 次
- 数据完整性问题（告警/指标丢失）
- 安全漏洞被发现

### 8.2 回滚步骤
1. **停止新流量**（Nginx 切换到维护模式）
2. **保留当前状态**（日志、监控数据、数据库快照）
3. **回滚应用**（切换到上一个版本的 Docker 镜像）
4. **回滚数据库**（运行对应的 down migration 脚本）
5. **验证回滚**（健康检查、核心功能测试）
6. **恢复流量**（逐步放开 Nginx 流量）
7. **监控确认**（持续 30 分钟观察）

### 8.3 回滚时间目标
- 停止流量：1 分钟
- 回滚应用：5 分钟
- 回滚数据库：10 分钟
- 验证恢复：5 分钟
- **总回滚时间：≤ 21 分钟**
